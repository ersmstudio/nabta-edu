# دليل المساهم وبيئة التطوير المحلية

أهلًا بك في نبتة 🌱. هذا الدليل يعرّفك بالموقع كما هو موجود في المستودع، ويجهز نسخة محلية آمنة للتجربة قبل نشر أي تغيير.

## 1. فكرة المنتج

نبتة منصة تعلّم وإبداع تستهدف من يريد البدء في مجال جديد بخطوات سهلة. التجربة عربية وإنجليزية، واتجاه الصفحة يتبدل مع اللغة. تتكون المنصة من واجهة عامة، ومسارات وكورسات، وحسابات للمتعلمين، وتجربة دروس واختبارات، ولوحة لإدارة المحتوى.

المكدس الحالي: Next.js 15 App Router، React 19، TypeScript، Tailwind CSS 4، Auth.js، Prisma 6، وPostgreSQL. مشغّل C# خدمة منفصلة تعمل بـNode وDocker و.NET 8.

## 2. ما الذي يستطيع الزائر فعله؟

### الصفحة الرئيسية واللغات

- استكشاف المسارات والبحث عنها، ومشاهدة نبذة «عن نبتة».
- التبديل بين العربية والإنجليزية من زر اللغة.
- اقتراح لغة المتصفح عند أول زيارة. يمكن للزائر اختياريًا مشاركة موقعه لاختيار اللغة بحسب الدولة؛ لا يُطلب الموقع دون موافقته.
- عند توفر بيانات من لوحة الإدارة، تقرأ الصفحة المسارات والنصوص المنشورة من `/api/site`. وإلا تعرض البطاقات التعريفية المدمجة كبديل.

### الحسابات

- التسجيل من `/register` بالبريد والاسم وكلمة مرور من 8 إلى 128 حرفًا.
- الدخول من `/signin`. تُخزّن كلمة المرور بعد تشفيرها باستخدام bcrypt، وتُدار الجلسة بواسطة Auth.js.
- أغلب عمليات إرسال الاختبارات وتشغيل الكود تتطلب تسجيل الدخول.

### التعلم

- استعراض المسار من `/paths/{slug}` ثم محتوى الكورس المنشور من `/learn/{course-slug}`.
- صفحة الدرس تعرض الفيديو والوصف والنص المفرغ عند إضافته، وأسئلة الدرس وتمارين الكود عند وجودها.
- أنواع الأسئلة المدعومة: اختيار واحد، اختيار متعدد، قائمة منسدلة، صح/خطأ، إجابة قصيرة، وإجابة مقالية.
- تُحسب الدرجات الموضوعية تلقائيًا. الإجابات المقالية تُعلّم للمراجعة، ويمكن للمدير اعتماد درجتها من لوحة النتائج.
- تُحفظ المحاولات وتسليمات الأكواد وتقدم الدروس في قاعدة البيانات.

### لوحة الإدارة

`/admin` متاحة للحساب الذي يطابق `ADMIN_EMAIL` في البيئة. من اللوحة يمكن إدارة المجالات والكورسات والدروس والأسئلة وتمارين C#، ومراجعة محاولات الاختبارات والتسليمات، وتعديل نصوص الصفحة الرئيسية والتعريف والتذييل. انظر [دليل لوحة الإدارة](./ADMIN-DASHBOARD.md) لتفاصيل النشر والمحتوى.

### تمارين C#

يُرسل كود الطالب إلى خدمة منفصلة، وتنفذ كل محاولة في حاوية مؤقتة بلا شبكة وبحدود وقت وذاكرة وموارد. إذا لم تشغّل الخدمة، يظل بإمكانك تصفح وإدارة التمارين، لكن التحقق من الكود غير متاح. الإعداد خطوة اختيارية موضحة في [دليل المشغّل](./C-SHARP-RUNNER.md).

## 3. تجهيز Local Dev على Windows

استخدم PowerShell من مجلد المشروع.

### أ. المتطلبات

1. ثبّت Node.js 20 أو أحدث وnpm.
2. جهّز قاعدة PostgreSQL محلية باسم `nabta_edu_dev`، أو قاعدة تطوير منفصلة لا تحتوي بيانات الإنتاج.
3. عند تجربة C#، ثبّت Docker Desktop وشغّله.

### ب. تثبيت المشروع

```powershell
npm install
```

أنشئ ملف البيئة **فقط إن لم يكن لديك ملف `.env` بالفعل**:

```powershell
Copy-Item .env.example .env
```

عدّل `.env` المحلي بهذه القيم، مع استبدال بيانات PostgreSQL:

```dotenv
DATABASE_URL="postgresql://USER:PASSWORD@localhost:5432/nabta_edu_dev?schema=public"
AUTH_SECRET="قيمة-عشوائية-طويلة-للتطوير-المحلي"
AUTH_TRUST_HOST=true
ADMIN_EMAIL="البريد-الذي-ستسجل-به-للوحة-الإدارة@example.com"
GEOCODING_URL="https://nominatim.openstreetmap.org/reverse"
```

استخدم سرًا محليًا من اختيارك، ولا تنسخه من الإنتاج. لا ترفع `.env` أو الأسرار إلى Git. `CODE_RUNNER_URL` و`CODE_RUNNER_TOKEN` لا يلزمان إلا عند تشغيل مشغّل C#.

### ج. تجهيز قاعدة البيانات وتشغيل الموقع

```powershell
npx prisma generate
npx prisma migrate dev
npm run db:seed
npm run dev
```

افتح `http://localhost:3000`. أمر seed يضيف المجالات الأولية وكورس C# المنشور وبعض الكورسات التجريبية بحالة مسودة، ويجهز إعدادات الموقع. أعد seed عند الحاجة فقط؛ هو يضيف أو يحدّث البيانات الأولية المعروفة ولا يمسح كل قاعدة البيانات.

لإنشاء migration بعد تعديل `prisma/schema.prisma`:

```powershell
npx prisma migrate dev --name describe-the-change
```

أضف ملف migration الجديد مع التغيير إلى Git. لا تستخدم قاعدة الإنتاج أثناء التطوير، ولا تستخدم `migrate reset` على بيانات مهمة.

### د. تشغيل تمارين C# محليًا (اختياري)

من PowerShell، اختر رمزًا عشوائيًا طويلًا (32 حرفًا على الأقل) وضع القيمة نفسها في طرفي التشغيل: `CODE_RUNNER_TOKEN` داخل `.env` الخاص بالموقع، وفي جلسة PowerShell التي تشغل Docker Compose.

```powershell
$env:CODE_RUNNER_TOKEN = "ضع-رمزًا-عشوائيًا-طويلًا-هنا"
docker build -f code-runner/Runtime.Dockerfile -t nabta-csharp-sandbox:8.0 code-runner
docker compose -f docker-compose.sandbox.yml up --build -d
```

وفي `.env`:

```dotenv
CODE_RUNNER_URL="http://localhost:8787/execute"
CODE_RUNNER_TOKEN="نفس-الرمز-المحلي"
```

أعد تشغيل Next.js بعد تعديل البيئة. لإيقاف الخدمة:

```powershell
docker compose -f docker-compose.sandbox.yml down
```

التفاصيل ومتطلبات Docker موجودة في [دليل المشغّل](./C-SHARP-RUNNER.md). لا تعرّض منفذ المشغّل للإنترنت.

## 4. جولة سريعة للتحقق يدويًا

بعد التشغيل، جرّب بنفسك:

1. الصفحة الرئيسية والبحث وتغيير اللغة على سطح المكتب والهاتف.
2. إنشاء حساب جديد، ثم تسجيل الدخول والخروج.
3. فتح `/admin` بالبريد المحدد في `ADMIN_EMAIL`، وإضافة مسودة أو تعديل نص تجريبي.
4. نشر مجال وكورس ودرس تجريبي ثم فتح المسار والدرس كمتعلم.
5. إرسال اختبار موضوعي وإجابة مقالية. الإجابة المقالية تحتاج مراجعة من اللوحة.
6. عند تشغيل Docker، أرسل تمرين C# صحيحًا وخاطئًا، ولاحظ نتيجة حالات الاختبار.
7. اختبر الموقع من دون تشغيل مشغّل الأكواد: يجب أن يوضح أن الخدمة غير مضبوطة بدل نجاح وهمي.

هذه جولة يدوية وليست بديلًا عن المراجعة أو الاختبارات الآلية عند إضافتها للمشروع.

## 5. خريطة الملفات

| المسار | وظيفته |
| --- | --- |
| `app/page.tsx` | الصفحة الرئيسية والتصفح والبحث |
| `app/locale-provider.tsx`, `app/i18n.ts` | اختيار اللغة والنصوص والترجمة |
| `app/courses/` | صفحات المجالات والكورسات التعريفية الموجودة في الكود |
| `app/paths/`, `app/learn/` | المسارات والدروس المبنية على بيانات قاعدة البيانات |
| `app/admin/` | صفحة لوحة الإدارة وواجهة تحرير المحتوى |
| `app/api/` | التسجيل، المصادقة، محتوى الموقع، الإدارة، الاختبارات والتحديات |
| `lib/auth.ts`, `lib/authorization.ts`, `lib/admin-auth.ts` | الجلسات وصلاحيات المدير |
| `prisma/schema.prisma`, `prisma/migrations/` | نماذج قاعدة البيانات وتغييراتها |
| `scripts/seed.cjs` | بيانات أولية للتطوير |
| `code-runner/`, `docker-compose.sandbox.yml` | خدمة تنفيذ تمارين C# المعزولة |
| `docs/` | أدلة المساهم والإدارة والكورسات والمشغّل |

المجلدان `app/courses/...` و`app/paths` يمثلان تجربتين: صفحات كورسات تعريفية ثابتة، وتجربة تعلّم تعتمد على محتوى الإدارة المنشور. عند إضافة ميزة، راجع الروابط من الصفحة الرئيسية والتجربتين حتى يظل انتقال المتعلم واضحًا.

## 6. الأوامر المفيدة

```powershell
npm run dev       # تشغيل التطوير
npm run lint      # مراجعة قواعد ESLint
npm run build     # بناء نسخة الإنتاج محليًا
npm run start     # تشغيل نسخة البناء
npm run db:seed   # إضافة بيانات التطوير الأولية
```

## 7. قبل النشر

- شغّل التغيير محليًا وراجع الصفحات بالعربية والإنجليزية وعلى الهاتف.
- راجع `git diff` وتأكد ألا يظهر `.env` أو أي مفتاح أو بيانات شخصية.
- شغّل `npm run lint` و`npm run build`، وطبّق migrations على قاعدة تطوير أولًا.
- لا تنشر محتوى تجريبيًا أو إجابات صحيحة/حالات اختبار في واجهة عامة.
- نشر المشروع الحالي مرتبط بفرع `main` وGitHub Actions على self-hosted runner؛ كل push إلى `main` يشغّل النشر. لا تدفع تغييرات إلى `main` بغرض التجربة. راجع إعداد النشر والأسرار في [دليل مشغّل C#](./C-SHARP-RUNNER.md) وملف `.github/workflows/deploy.yml` قبل أي نشر مقصود.
- تأكد أن أسرار الإنتاج مثل `DATABASE_URL` و`AUTH_SECRET` و`ADMIN_EMAIL` و`CODE_RUNNER_TOKEN` مضبوطة في GitHub Actions وفي بيئة الخادم، وأن قاعدة الإنتاج هي الوجهة المقصودة للـmigration.

## 8. أسلوب العمل المقترح مع المساهم

1. اشرح المهمة وسلوك المستخدم الذي نريد الوصول إليه.
2. اتفقوا على صاحب القرار في التصميم، مراجعة الكود، وقرار النشر.
3. اعملوا على فرع منفصل لكل تغيير، واستخدموا pull request للمراجعة.
4. اكتبوا خطوات إعادة إنتاج المشكلة ونتيجة متوقعة قبل تعديلها.
5. حدّثوا التوثيق عند تغيير إعدادات التشغيل أو مسارات المستخدم أو محتوى الإدارة.
6. لا تضعوا بيانات اعتماد حقيقية في الفيديو أو لقطات الشاشة أو ملفات التوثيق.
